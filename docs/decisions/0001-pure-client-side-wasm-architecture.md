# 1. 采用纯客户端 WASM 无后端架构

- **状态**: Accepted
- **日期**: 2026-09-20 (从初始提交及配置确认)
- **决定者**: 核心架构设计

## 背景与问题

传统 AI 图像像素化服务通常采用前端上传图片到后端服务器、由后端持有密钥调用大模型生成并使用 Python/Pillow 像素化后回传。这种架构存在以下痛点：
1. **服务端运维与带宽成本高**：需要长期运行后端服务、处理图片传输和高并发计算。
2. **凭据安全与隐私风险**：集中式托管要求将用户 API Key 传输并暂存到服务端，存在数据泄露风险。
3. **部署复杂度高**：无法仅通过静态 CDN 或轻量 Nginx 容器一键分发。

## 决策

1. 将整个应用构建为**纯静态单页应用**，不包含任何业务后端服务。
2. 在浏览器端通过 Web Worker 运行 **Pyodide WASM (CPython 运行时 + Pillow + NumPy)**，直接在用户浏览器中执行全部像素化计算。
3. 由浏览器端通过 Pyodide `pyfetch` 直接向 Gemini 官方端点或用户指定的网关发起 REST 调用，API Key 仅保存在客户端。
4. 部署形式仅为静态文件分发（Nginx:alpine 或任意静态托管）。

## 结果与影响

### 正面影响
- **零服务器成本**：无后端计算开销与图片中转带宽压力，服务端只需托管静态文件。
- **高隐私与安全性**：用户 API Key 永不离开本地浏览器。
- **一致的像素化能力**：复用成熟的 Python 图像生态（Pillow / NumPy），无需用 JavaScript 重写复杂的图像降采样算法。

### 负面影响 / 权衡
- **首屏加载包体较大**：首次冷启动需要从 CDN 或自托管源下载 Pyodide 核心包（约 7.5MB）。
- **客户端网络要求**：使用者所在网络必须能从浏览器直连模型 API 端点；若使用自定义代理网关，网关必须配置正确的 CORS 头。
- **取消操作开销**：中断正在运行的 WASM 计算需要通过 Terminate Worker 并重启 Worker 来实现。
