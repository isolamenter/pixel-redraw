# 5. 采用 256 参考画布比例映射作为像素密度基准

- **状态**: Accepted
- **日期**: 2026-09-24
- **决定者**: 核心算法设计与前端架构

## 背景与问题

在像素化重构的初期草案中，曾尝试将 UI 上的 Density（密度档位）直接定义为“输出图像最长边的固定像素数”（即无论原图是 512×512 还是 2048×2048，Density 32 都会输出固定 32×32 网格）。这种设计在实际应用中带来了严重的体验与架构缺陷：
1. **失去颗粒度控制能力**：对于高分辨率输入图，固定输出尺寸会强行丢弃大量空间信息；而如果用户想要更细腻的像素表现，不得不引入 256、512 等过大档位。
2. **长宽比例失衡与溢出风险**：在长宽比较大的非正方形图像（如超宽横屏或全景图）中，按最长边固定尺寸会导致短边网格被极度压缩；而超大档位（如 256/512）在极端分辨率下极易导致内存爆炸或 WASM 计算超时。
3. **概念混淆**：“密度（Density）”原本代表单位视觉空间内的采样疏密程度，若改为“固定输出分辨率”，其语义与直觉严重脱节。

## 决策

1. **确立 256px 参考画布比例映射**：
   - 将 Density（$D$）定义为以 256px 为逻辑基准画布时的网格划分数。
   - 目标逻辑尺寸公式统一为：
     $$W_{grid} = \max\left(1, \operatorname{round}\left(\frac{W_{src} \times D}{256}\right)\right), \quad H_{grid} = \max\left(1, \operatorname{round}\left(\frac{H_{src} \times D}{256}\right)\right)$$
2. **统一标准密度档位**：
   - 确立标准预设五档：`SIZES = (8, 16, 32, 64, 128)`，默认密度设为 `32`。
   - 彻底废除临时的 256 / 512 补丁档位。
3. **保持端到端一致性**：
   - Python 核心算法（`pixel_reduce.py`）、WASM 桥接层（`pixel_pipeline.py`）以及前端 UI 选项（`static/js/`）严格基于该比例模型进行计算与渲染。

## 结果与影响

### 正面影响
- **语义清晰且符合直觉**：Density 纯粹控制像素艺术的“块大小/颗粒度”，相同密度在不同分辨率下呈现一致的视觉质感。
- **天然保真宽高比**：非正方形图片宽高独立等比缩放，杜绝拉伸变形与边缘非对称劣化。
- **系统稳健性**：消除了 256/512 超大档位带来的 WASM 内存溢出与性能风险。

### 负面影响 / 权衡
- 输出图像的最终逻辑分辨率会随输入图原始尺寸线性缩放（如 1024×1024 在 Density 32 下输出 128×128），而非固定尺寸。对于需要绝对固定输出尺寸的特定游戏引擎切图场景，需先在外部裁剪或缩放输入图。
