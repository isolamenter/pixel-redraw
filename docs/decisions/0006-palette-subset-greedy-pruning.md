# ADR 0006: 调色板最大颜色数限制与加权感知误差贪心剪枝

## 1. 状态 (Status)
**Accepted** (2026-09-24)

---

## 2. 背景与上下文 (Context)
在像素画创作中，用户往往希望使用特定机能或主题调色板（如 64 色的 AAP-64 或 16 色的 PICO-8），但同时希望画面风格更加极简与克制（例如将实际画面使用的颜色数量限定为 4 色、8 色或 16 色）。

如果在全量调色板映射后单纯按像素出现频次截断（Top-K Frequency），会导致背景或大面积区域的相近色占满名额，而画面关键的高对比特征色（如眼睛高光、红唇、微小装饰物等）因像素数量少而被完全吞没。

为了解决这一问题，系统需要一种**在指定调色板内挑选出对当前画面最具代表性的 $K$ 色子集**的算法。

---

## 3. 决策 (Decision)

### 3.1 加权感知误差贪心剪枝算法 (Weighted Perceptual Error Greedy Pruning)
在 [`pixel_color.py`](file:///Users/akiya/Project/pixel/pixel_color.py) 中实现 [`select_sub_palette(rgb_samples, palette, max_colors)`](file:///Users/akiya/Project/pixel/pixel_color.py#L254-L336)：
1. **初次映射与加权**：将图像中所有不透明像素映射到完整调色板 $P$，统计各色索引的有效像素数量 $w_i = \operatorname{count}(i)$。
2. **有效集判定**：提取有效激活颜色集 $Active$。若 $|Active| \le K$，直接保留该子集（保持原色板排序）。
3. **感知误差贪心剪枝**：若 $|Active| > K$，在 Oklab 感知色彩空间中迭代消除颜色：
   - 对于每个候选颜色 $i \in Active$，计算将其移除并归并到其最近邻颜色 $j^*(i) = \arg\min_{j \in Active \setminus \{i\}} \| C_i - C_j \|_{Oklab}^2$ 所带来的加权感知误差增量：
     $$\Delta E_i = w_i \cdot \| C_i - C_{j^*(i)} \|_{Oklab}^2$$
   - 每次贪心剔除 $\Delta E_i$ 最小的颜色 $i^*$，将其权重 $w_{i^*}$ 累加至其最近邻 $j^*(i^*)$，重复循环直至 $|Active| = K$。
4. **子集与平局稳定性保证**：输出的 $K$ 色严格按原调色板中的索引升序排列，继承原色板的低位索引平局裁决特性。

### 3.2 UI 与交互层常驻呈现
1. **面板结构重组**：自定义 Hex 输入框移至顶部；预设色板去除色块条；最大颜色数控件支持 `全部 (All)` 与 `指定数量`（在 Auto 模式下置灰禁用但不隐藏）。
2. **Pal Echo 独立常驻**：在面板底部永久显示本次实际使用的调色板方格与 Hex 色值。
3. **0 Token 即时重新量化**：调整最大颜色数时，直接触发本地 Repixelize，无需调用大模型。

---

## 4. 影响与结果 (Consequences)

### 积极影响 (Positive)
- **特征色高度保全**：高对比度、远距离的孤立重要色彩即使像素占比极低，其 $\|C_i - C_j\|^2$ 巨大，能够在剪枝中稳定存活；大面积密集的相近色调会被优先合并。
- **确定性与子集闭包**：100% 确定性算法，无随机种子依赖，严格满足子集不变量断言。
- **纯计算与毫秒级执行**：在 WASM 环境中耗时 $< 1$ 毫秒，计算复杂度 $O(M^2)$（$M \le 64$）。

### 权衡与约束 (Trade-offs)
- 当用户在复杂画幅上限定极少颜色数（如 2 色）时，算法会保证全局感知加权误差最小，但极度压缩会导致部分区域色彩对比度强烈极简化。
